- KI-006 AI vision reading output cap cuts off long scanned invoices — Evidence: doc-4 failed with `invalid_output` in D112 after using exactly 3386 output tokens (the per-call cap `min(4096, 8192 - ceil(prompt/3) - 3500 - 256)` in `runner.py:262-286`). The 5-page invoice of D112 succeeded, so this is about dense pages, not page count. Measured input tokens per page call across all D112 requests were consistently 3774 tokens; replacing the static 3500 image estimate with measured input tokens yields `8192 - 3774 - 256 = 4162` (capped at 4096), granting +710 tokens (+21% output room). Caveat: image tokens depend on the page shape (pixel area at max side 2048), so a single lower fixed estimate could overflow the 8192 window on Letter or square pages (a failed reading, never a wrong value); prefer an estimate from each page's real size, or a larger server context. — Impact: dense scanned invoices fail AI reading — Repro: an AI reading of doc-4 (page 1) on the company vLLM server. — Status: not reproduced in the D116 retry (3 calls, 4678 output tokens in all, no invalid output; per-call split not stored); still a hypothesis.
